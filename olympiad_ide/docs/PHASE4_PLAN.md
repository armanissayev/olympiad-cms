# Phase 4 implementation plan

Repository inspection: React/Monaco/Zustand, Dexie v3, PostgreSQL/FastAPI/Alembic, append-only telemetry and shared model ownership are already implemented. The existing `testCases` IndexedDB store is preliminary; there is no server test table, worker, execution queue or terminal library. Run/Stop and tests currently explain unavailability. Preserve editor/model ownership and both existing journals.

1. Add typed execution contracts and immutable, bounded manifest snapshots captured directly from live models/store. New SQL tables hold snapshots, jobs, results, ordered job events, worker leases/health and revisioned configuration/test resources. Do not update workspace revisions when submitting runs.
2. Implement owner-scoped resource CRUD with optimistic revisions, durable PostgreSQL queue/admission and idempotent submissions. One Run All job owns one source snapshot and compiles once; individual tests execute sequentially under its lease. Terminal status/results are durable independently of SSE connections.
3. Separate worker control from participant execution. Use Linux `isolate` with cgroup v2, resource limits, no inherited credentials/network, explicit toolchain commands and safe artifact extraction into fresh per-test boxes. Never execute participant code in the API or as a macOS fallback. Fence lease writes by opaque token and mark abandoned work infrastructure-error, not successful; retry is explicit new submission.
4. Reuse/extend Dexie's testCases table and add an independent revisioned resource outbox for configurations/tests. Preserve offline conflicts without overwriting remote resources. Persist active configuration, stdin and pending submission IDs for uncertain-ack retry/reload recovery.
5. Implement xterm.js output, bounded resumable SSE plus polling recovery, fixed stdin, history, Run/Stop, configuration and test CRUD/Run All UI in existing compact panels. Treat terminal data as output, not an interactive shell.
6. Extend existing typed RUN contracts with snapshot/configuration/status correlation, recording only observed actual lifecycle transitions. Persist deduplication per job so reload does not invent execution events. No execution depends on telemetry writes succeeding.
7. Test schema upgrades, ownership, immutable snapshots, concurrency/admission, cancellation/lease fencing, events, output comparison, local conflicts, UI and old regressions. Supply real Linux language/security suites and contest-load tooling; document exact results and unverified requirements.

Environment/release boundary: macOS has no Docker/Colima/isolate or existing Linux worker. The user explicitly confirmed no Linux target is available and asked to document this blocker. Linux sandbox/program/security and Docker/VM deployment verification therefore cannot be claimed here. Build a fail-closed worker, not an unrestricted substitute, and report Phase 4 incomplete until those acceptance tests pass in Linux. No 300-participant execution-capacity claim without measurement.
