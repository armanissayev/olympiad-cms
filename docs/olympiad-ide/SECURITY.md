# Security boundaries and release review

| Boundary compromised | Consequence and containment |
| --- | --- |
| Participant/browser | Can modify its own source and fabricate/drop browser telemetry. CMS rechecks session/task/policy; input owner IDs, clocks, hashes and official flags grant no authority. Local storage is not encrypted against the browser profile's owner. |
| Native CMS service | Trusted with CMS session validation, database and source admission; compromise threatens contest authority. Keep it unprivileged, on loopback behind TLS, with reviewed CMS dependencies and no sandbox-helper access. |
| Private runtime | Can read/change IDE data and possesses the dedicated HS256 secret, so compromise can forge IDE principal assertions. It has no CMS database/RPC credentials or CMS cookie signing key and cannot create official submissions. HS256 is not asymmetric isolation from a compromised verifier. |
| CMS database/storage | Can alter official source/receipts/results; protect roles/backups and audit access. Unique receipts protect concurrency, not a malicious DBA. |
| IDE database | Can alter workspace/telemetry/custom jobs and nonce records; no direct CMS authority. Separate roles and database prevent migration overlap. |
| Trusted worker/controller/helper | Handles untrusted custom programs and real debug adapters/debuggees through isolate; helper compromise threatens its dedicated worker host. No CMS DB, judge data or RPC route should exist there. |
| Untrusted program | Limited to an approved fresh isolate sandbox, bounded CPU/wall time/memory/processes/output and no credentials or external networking. Debug adapters use only loopback inside their fresh network namespace. Linux tests must verify this on the actual worker host; never substitute unrestricted subprocess execution. |

## Enforced controls

- Real CWS session/participation/phase checks, XSRF mutations, expected-principal switch detection and server task membership.
- Request-bound PyJWT assertions with issuer/audience/expiry, exact query/body hashes and durable one-use nonce. Direct unauthenticated private calls fail closed.
- Fixed loopback private origin; method/path/query allowlist, no redirects, no arbitrary RPC or environment proxies. Incoming identity headers do not become trusted claims.
- Body/source/file/import limits, strict UTF-8, canonical UUIDs and file mapping, current ownership checks for workspace/telemetry/job/receipt identifiers. STDOUT and compiler/runtime diagnostics render as inert React text, without HTML injection. The current workbench has no interactive terminal emulator, Terminal/Problems/Test Cases tabs, saved run list or Run All control; Run captures only the active file. Historical terminal/Run All evidence describes the earlier UI.
- Separate native/runtime connection limits/timeouts; official requests have reserved HTTP capacity and ingress rate zone. PostgreSQL locks serialize quota admission across CWS and native shards.
- Private workspace reservations are bounded per stable principal (CMS_MAX_WORKSPACES default100, maximum1000); existing telemetry/execution quotas and retention remain. Reservations from malformed/abandoned creates count toward this conservative limit rather than creating an unlimited metadata channel.
- API responses use no-store; service worker caches only exact public application assets. No CMS secrets, assertions, cookies or passwords are included in source snapshots, journals or recording.
- Dedicated mode0600/0400 assertion files, no symlink key paths, no example secrets, no credentials in source-import/package manifest.

## Deployment controls

TLS is mandatory; use the supplied nginx cookie/forwarding protections and private listener rules. Allow participant network access only to443; restrict administrator access separately. PostgreSQL, CMS RPC, private runtime and worker control ports must not be contestant-accessible. SSH/monitoring access is operator-controlled. The initial rehearsal changed no AWS security group; the later explicitly authorized80/443 public-staging change is recorded below. No production DNS/network setting was changed.

Use a dedicated API OS account without isolate privileges and a dedicated worker host/account with execution-only IDE DB grants. The native CMS account has no private IDE DB credentials. The CMS and IDE migration roles are separate. Worker network policy must prevent CMS RPC/database/judge-data access; SQL grants alone do not constrain network reachability. Required Linux isolate privilege/cgroup setup stays explicitly gated by WORKER_SANDBOX_APPROVED; do not broadly disable system protections.

Configure storage quotas/retention and monitor database size, queue age, failed worker leases, request latency and authentication errors. Existing telemetry retention maintenance is an operator job; retaining raw telemetry indefinitely is not implied. Logs must redact cookies/assertions/request bodies and not copy participant code into CMS LogService. Browser recording scope/disclosure and manipulability remain visible.

## Restricted debugger boundary

Debug REST admission, ticket issuance and authorization refresh pass native CMS session/XSRF/principal/task/phase checks and the existing standalone stdin/stdout Batch capability guard. The API recomputes the immutable source hash and rejects reserved debug artifact paths. Official Submit and CMS judging do not depend on debug availability. A captured program remains unchanged when the live editor changes; breakpoint relocations apply to the next capture.

Only the exact canonical-UUID `/ide/api/debug/sessions/{UUID}/dap` WebSocket route reaches the private ASGI queue broker. Ordinary REST traffic still passes the native CMS gateway. This narrow exception is required because the pinned WSGI native stack does not upgrade WebSockets. Nginx rejects queries, overwrites forwarding/upgrade headers and strips client Authorization; it exposes no generic runtime or adapter route. The broker requires an exact configured Origin and a random opaque token in its first frame within5seconds. Tokens are never URL parameters; only their SHA256 is persisted. Each token expires after30seconds and is consumed once under a row lock. Fresh CMS-authorized tokens renew the connection every20seconds. Invalid/replayed/expired tickets cannot cancel a session they never authenticated. Authenticated disconnect/authorization expiry cancels the session; cancellation-shielded cleanup waits for its DB commit, while the worker's independent deadline/heartbeat remain fallback controls.

The allowlist permits source-bound unconditional breakpoints, threads/stack/scopes/variables and stepping/pause/continue/disconnect. DAP attach, arbitrary launch/environment/path arguments, expression evaluation, memory writes, conditional/log breakpoints and reverse `runInTerminal` are denied. The worker replaces initialize/launch settings with trusted language profiles. Adapter state/values come from real GDB/debugpy/JDI, never a UI simulation. Debug values/stdout/diagnostics render as inert text.

Limits are32active/unexpired sessions globally, one active/principal,20starts/hour/principal, a fixed five-minute deadline from admission,1000commands/session,20commands/second,5000events and1MiB output/session. Uvicorn rejects inbound WebSocket messages over32768bytes and queues at most4; application validation is additional. Worker DAP frames cap at64KiB, and its nonblocking adapter-input queue caps at64KiB so stalled stdin cannot block Stop. Worker lease/heartbeat checks fail closed on cancellation, stale leases, DB loss or expiry. Session expiry does not erase persisted source/journals; operator retention is required.

`worker.app.debug_main` is a separate service/process using dedicated isolate box600; ordinary custom Run uses200, native judging0 and tests610–650. The staging custom/debug units use the dedicated ideworkerstage account; this is process/box separation, not separate OS identities for those two IDE workers. Each adapter and debuggee share a fresh isolate PID/mount/network namespace, sandbox UID and cgroupv2. Only that namespace's loopback is available, with no `--share-net`, host CMS socket mount, key or DB credential inheritance. Adapter/debuggee execution limits are30CPU seconds,300wall seconds,1GiB aggregate memory,64processes/threads,128file descriptors and1MiB per-file writes, with syscall policy31. Compilation uses the existing separate Sandbox compilation profile:30CPU/wall seconds,512MiB memory,64processes,64file descriptors and64MiB per-file writes. The64MiB/1024-inode filesystem quota bounds the whole box in both phases. The pre-created immutable source capture may exceed the execution per-file write limit, within admission limits. These do not loosen ordinary Run policy. Stop/timeout/output failure/transport cancellation clean up both adapter and debuggee. Root-owned helpers are read-only to the controller; no unrestricted subprocess fallback is provided.

Both `WORKER_SANDBOX_APPROVED=1` and the separate `DEBUG_SANDBOX_APPROVED=1` must be present before debug capacity is advertised or claimed. The initial actual Linux debug suite passed8cases in5.13s; the final suite passed10cases in5.05s, with both approval variables unset and no skips. The latter consists of4protocol/backpressure policy checks and6real Linux isolation cases, separate from the unchanged26mandatory Run tests and the three real language probes. Review all evidence before enabling either applicable approval; passing a control-plane unit test cannot replace real isolation prerequisites. Exact deployment and acceptance results are in [WORKBENCH_ACCEPTANCE](WORKBENCH_ACCEPTANCE.md), [Phase6 architecture](../../olympiad_ide/docs/PHASE6_ARCHITECTURE.md), [initial debug evidence](evidence/phase6/linux-debug-prerequisites.log) and [final debug evidence](evidence/workbench-vnext/debug-security-final.log). Public-browser Pause/Stop acceptance is reported there separately; these prerequisite counts do not establish it.

The [installed adapter provenance/licensing audit](JAVA_DEBUGGER.md) covers distro GDB17.1, debugpy1.8.19 with vendored PyDev notices, OpenJDK17/JDI and the project-owned standalone adapter/wrappers. It does not certify every transitive licence/advisory or remove the original IDE attribution release gate.

## Limitations

CMS1.5.1's old stack and upstream authentication semantics remain; this is not a CMS-wide security modernization. Pinning dependencies is not a vulnerability audit. Review deployment dependency advisories and imported-source licensing before release. The authorized Linux rehearsal verified cgroup v2, user quotas, syscall restrictions, execution-only helper access (4750), separate official/custom accounts, web/API NoNewPrivileges, custom PrivateNetwork, restricted DB/file access, component/DB faults and matched database/application restoration. See LINUX_ACCEPTANCE and its actual boundary/syscall reports. A shared staging kernel remains a common root-helper failure domain; dedicated production execution hosts, off-host recovery and representative load limits still require review.

Unit tests with fixture scores do not certify hidden-data isolation in every third-party CMS task/score plugin. Unsupported task types fall back explicitly. The first supported topology is one contest and loopback runtime; multi-host runtime transport needs a new reviewed authenticated-channel design.

## Submitted-file history review — 5 November 2026

The new Admin viewer selects actual CMS submitted files after a participant/problem choice and groups recorded source changes into occupied 1/5/10/30-second intervals (default 5). It hides raw cursor/focus/key-release/navigation noise while retaining source edits, explicit boundary snapshots and useful review cues. Previous/next, activity overview, seek, skip-wait playback, before/after comparison and marked-period filtering operate on read-only source. Identity/file changes clear prior source and abort/fence delayed requests; playback tokens prevent concurrent stale timers. Final deployment/current evidence is recorded separately in [FILE_HISTORY_ACCEPTANCE](FILE_HISTORY_ACCEPTANCE.md). Earlier 4 November public-access acceptance remains historical evidence, not proof of the new viewer.

Native listing reads actual CMS Submission/File records scoped to the current contest Participation and Task. An enabled full-permission CMS Admin session is required for every page/data request. For timeline/replay, the native service validates the immutable receipt's installation/identity scope and exact source manifest, then signs its workspace/file/capture-session/sequence/hash/submission-time query. Browser capture parameters cannot replace those values. Runtime checks the stable principal, task/workspace binding and retained period bounds. Standard CWS files and missing/invalid receipt links are explicitly unavailable for history; they are not associated with a recording by filename similarity or guessed times. Existing normal CMS submission links remain available. No new table, migration, database grant, collection permission or role is introduced.

The captured recording is capped at its exact receipt sequence. Earlier periods remain separate, use the same authorized workspace/file and stop before their first event uploaded after submission. Later recordings and out-of-bound positions are rejected. Late offline uploads may consequently be absent and that limitation is disclosed. Analysis is bounded to the captured plus at most 30 earlier periods,10,000 relevant rows and 6,000,000 serialized payload bytes; it prioritizes the captured period and explicitly marks truncation. Unused session replay-state fields are deferred and checkpoint candidates streamed. Reconstruction retains its verified checkpoint/5,000-event segment limit and returns only the selected file through the new API. Missing, corrupt, expired or incomplete source is disclosed rather than invented; a submitted-byte hash match is a snapshot comparison, not proof of authorship or uninterrupted writing.

Review rules identify observed paste, Ctrl/Cmd+C shortcuts, single insertions of at least 200 UTF-16 code units, at least 1000 units across multiple ordinary edits within 10 seconds, pauses of at least 120 seconds, and slow observed editing below 20 inserted units/minute over at least 300 elapsed seconds and 10 keyboard-linked changes. Elapsed time includes pauses. Slow-rate calculation excludes linked observed paste transactions; undo/redo and programmatic changes are excluded from large/rapid/slow writing cues. File creation/recovery/generated changes remain explicit context. Keyboard totals count source transactions correlated with key-down records, not every physical key. Threshold details and UTF-16 units are described in [ADMIN_HISTORY](ADMIN_HISTORY.md).

These are human-review cues, with no automatic plagiarism verdict, ranking, sanction or inference of an untrusted paste source. Inserted editor text, including pasted code, is already recorded; no additional OS-wide keyboard or clipboard collection, raw clipboard read, external-app monitoring, source website/app detection or cross-participant code comparison is added. Paste provenance is **unknown**, not trusted or untrusted. Copy shortcuts do not prove clipboard transfer. Thinking, reading, accessibility tools, completion, formatting and legitimate reuse can explain unusual activity; a lack of markers does not prove authorship. Browser telemetry remains participant-controllable and hashes do not prevent a malicious browser or database administrator from fabricating history.
